# 好友棋牌房 · 在线玩牌网页应用

一个前后端一体的小网站：**打开网址 → 填昵称 → 建房/进房 → 叫朋友输房间号就能一起打牌**。
不需要注册登录，不需要上架应用商店，不需要数据库。

支持四款游戏：**港式五张牌（梭哈）、唬牌（吹牛/骗牌）、保皇、升级（拖拉机）**。

技术栈：Node.js + Express + Socket.IO + 原生 HTML/CSS/JavaScript（**没有编译、没有打包**），
只占一个端口，部署到任何免费云平台都很省事。

## 二、本地运行（3 步）

### 第 1 步：装 Node.js

去 <https://nodejs.org> 下载 **LTS（长期支持版）**，一路下一步装完。
装完打开**新的**终端窗口，输入下面两条命令验证：

```bash
node -v
npm -v
```

能显示出版本号（例如 `v20.11.0` / `10.2.4`）就说明装好了。

> 本项目要求 Node **18 或更高**。如果版本低于 18，请重新下载 LTS 版。

### 第 2 步：安装依赖

在终端里进入项目目录（把路径换成你自己的）：

```bash
cd card-party
npm install
```

看到 `added 89 packages` 之类的提示就成功了，会多出一个 `node_modules` 文件夹。

### 第 3 步：启动

```bash
npm start
```

看到下面的输出就说明跑起来了：

```
==============================================
  好友棋牌房已启动
  本机访问： http://localhost:3000
==============================================
```

浏览器打开 **http://localhost:3000** 就能玩了。
停止服务：在终端按 `Ctrl + C`。

### （可选）跑一遍自检

```bash
npm test
```

会模拟几百局随机对局，检查规则有没有崩溃、计分是否配平。全部 `通过 N 项，失败 0 项` 就正常。
（这一步不需要任何额外依赖，也不需要启动服务。）

另外还有两个「端到端」脚本，会用真实的客户端连服务器跑一遍建房/进房/出牌/重连，
需要先启动服务、并额外装一个测试用依赖：

```bash
npm install socket.io-client --no-save
node scripts/e2e.js        # 唬牌：建房 → 加入 → 出牌 → 质疑 → 掉线重连 → 解散
node scripts/e2e-all.js    # 四款游戏各走一遍
```

## 三、常见问题排查

| 现象 | 原因 / 解决办法 |
|---|---|
| `'node' 不是内部或外部命令` | Node.js 没装好，或装完后没**重开终端**。重启电脑还不行就重装 LTS 版。 |
| `npm install` 卡住 / 很慢 | 换国内镜像：`npm config set registry https://registry.npmmirror.com`，然后再 `npm install`。 |
| `Error: Cannot find module 'express'` | 依赖没装。确认终端当前目录是 `card-party`（里面有 `package.json`），再执行一次 `npm install`。 |
| `EADDRINUSE: address already in use :::3000` | 3000 端口被别的程序占了。换端口启动：<br>Windows：`set PORT=4000 && npm start`<br>Mac/Linux：`PORT=4000 npm start` |
| 页面能打开，但一直显示"等待开始"/没反应 | 打开浏览器按 F12 → Console，看有没有红色报错。最常见是 `/socket.io/socket.io.js` 加载失败，说明部署平台屏蔽了 WebSocket（换 Render / Koyeb / Railway 这类支持 WebSocket 的平台）。 |
| 手机连不上电脑上的服务 | ① 电脑和手机要在**同一个 WiFi**；② 地址不能用 `localhost`，要用电脑的**内网 IP**（Windows 在终端输入 `ipconfig` 找「IPv4 地址」，一般是 `192.168.x.x`）；③ Windows 防火墙可能拦截，临时关闭防火墙或允许 Node.js 通过。 |
| 朋友说点了没反应 / 掉线 | 免费云平台一般会休眠（见第五节）。第一次打开要等 30 秒左右，之后就正常了。 |
| 加入了但提示"牌局进行中" | 本局已经开始，等这局结束（房主点「下一局」）再加入；刷新页面通常能自动回座位。 |
| 五张牌提示"本游戏最多 5 人" | 这是正常的：牌组只保留 8~A 共 28 张，每人 5 张，所以最多 5 人。 |
| 五张牌打完一局就卡住 | 房主需要在结算界面点「**继续游戏**」才会进入下一局；只剩一位有筹码时会自动结束并出现「重新开始」。 |
| 我想清空所有房间 | 重启服务即可。所有房间数据都存在内存里，重启就清空（这是刻意设计，不需要数据库）。 |

## 四、四款游戏规则速查（本实现采用的玩法版本）

更详细的规则说明写在每个 `server/games/*.js` 和 `public/shared/*.js` 的**顶部注释**里，
有歧义的地方都注明了「按哪种通行做法」，想改规则直接改注释旁边那几行即可。

### 1. 港式五张牌（梭哈）· 2–5 人
- **牌组点数只保留 8、9、10、J、Q、K、A（2~7 已剔除）**，共 7 点数 × 4 花色 = **28 张**。
  牌更少 → 下注轮次更少、成牌更快、一局时间更短；代价是 `28 ÷ 每人 5 张 → 最多 5 人`。
- 每人 5 张：**1 张暗牌 → 3 张明牌（每发一张下注一轮）→ 第 5 张暗牌 → 再下注一轮**，共 4 轮下注。
- 第 1 轮由庄家下家先说话；第 2 轮起由**明牌最大**的人先说话。
- 动作：弃牌 / 让牌 / 跟注 / 加注 / 全下。支持边池（all-in 分层结算），未被跟注的下注会退还。
- 牌型：同花顺 > 四条 > 葫芦 > 同花 > 顺子 > 三条 > 两对 > 一对 > 散牌。
  因 2~7 已剔除，**A2345 小顺子不可能出现**；最大顺子为 A K Q J 10。
- 完全同点时默认比花色 ♠>♥>♦>♣（可在房间里关掉，关掉则平分）。
- 房间选项：初始筹码、底注、加注单位、每轮加注次数上限、是否比花色。
- **连局机制**：每局结束后点「**继续游戏**」进入下一局，筹码累计；
  当只剩一名玩家还有筹码时**自动结束**，结束界面显示最终排名，房主可点「**重新开始**」重置筹码。

### 2. 唬牌（吹牛 / 骗牌）· 2–8 人
- 一副牌全部发完（可选加 2 张万能王）。持有 **♠A** 的人先喊牌。
- **喊牌**：轮到你时，从手牌扣下**至少 1 张**牌，背面朝下放进本圈，并公布声称的牌型，
  例如「**两张 7**」。喊的张数 = 实际扣下的张数，点数可以撒谎。
- 下家三选一：
  - **质疑**：除喊牌者本人外**任何玩家**都能发起（谁先点谁获得资格）。掀牌验证：
    - 喊的是**假** → 本圈所有牌归**喊牌者**；
    - 喊的是**真** → 本圈所有牌归**质疑者**。
    - 收牌的一方继续出牌喊牌。
  - **跟牌**：至少跟 1 张，新喊的牌型必须**压过**上家——**张数更多**，或**同张数点数更大**。
    例：上家「两张 7」，你可以喊「三张 7」或「两张 9」。
  - **放弃**：信任上家并跳过。若除喊牌者外**所有人都放弃**，本圈累积的牌作为
    **淘汰牌**永久移除，不再翻开。
- **点数大小**：A > K > Q > J > 10 > … > 4 > 3 > 2 > 小王 > 大王（A 是最大的普通牌，2 最小）。
- **胜负判定**：**率先出完手牌者获胜**，游戏立即结束。
  - 为防止"用最后几张牌吹牛瞬间赢"，出完手牌后会进入一个**质疑确认窗口**
    （默认 15 秒，可调）：窗口内无人质疑才判胜；被质疑且属实 → 质疑者收牌但出完者依然获胜；
    被质疑且是假 → 出完者收走本圈所有牌，游戏继续。
- **计分**：输家按**剩余手牌每张牌的点数**扣分，赢家获得全部输家的分数。
  每张牌分值 = 该牌点数（A=14、K=13、…、2=2、小王=15、大王=16）。
- **超时**：30 秒无响应自动代为放弃；该领出时自动出手里最小的 1 张并如实喊出。
- 房间选项：无响应自动放弃秒数、出完手牌后的质疑窗口秒数、是否加 2 张王当万能牌。

### 3. 保皇 · 4–5 人
- **4 副牌 216 张**。5 人时皇帝 44 张、其余 43 张；4 人时每人 54 张。
- 随机一张大王做「皇牌」，拿到的是**皇帝**，皇帝先出牌（所以皇帝身份公开）。
- 皇帝选 **独保**（1 打 N，基础分 24）或 **叫保**（指定保子牌，如小王/♠3…，基础分 12）。
- 拿到保子牌的是**保子**，可选**明保**（身份公开、分数翻倍）或**暗保**。
- 牌型：单 / 对 / 三 / 三带一 / 三带二 / 顺子(≥5) / 连对(≥3对) / 飞机(≥2组) / 炸弹(≥4) / 王炸(≥2张王)。
- 牌点：3<4<…<A<2<小王<大王。**王只能单出或凑王炸**。
- 保皇派两人全出完 = 保皇派胜；革命派全出完 = 革命派胜。

### 4. 升级（拖拉机）· 固定 4 人
- **2 副牌 108 张**，对家结队（0/2 号座一队、1/3 号座一队）。
- 每人 25 张，庄家多拿 8 张底牌；庄家先**选主花色**，再**扣回 8 张底牌**（可点「自动扣牌」）。
- 主牌 = 大小王 + 所有级牌 + 主花色全部牌。
- 牌型：单张 / 对子 / 拖拉机（同门相邻的对子，≥2 对）/ 甩牌（同门多张混出，必须压得住人）。
- 跟牌张数必须相同；有该门牌必须先出该门，不够可用主牌「毙」。
- 5=5 分、10=10 分、K=10 分。**闲家得分 ≥80 即上台**。
- 升级表（闲家得分 D）：0→庄家升3级；<40→升2；<80→升1；<120→闲家上台升1；<160→升2；≥160→升3。
- 闲家赢最后一轮 = **抠底**，底牌分 ×2（用主牌抠底 ×4）。级数走到 A 之后再升级即通关。
- 房间选项：起始级数、是否允许甩牌、抠底是否翻倍。

## 五、免费部署上线（推荐 Render，最省事）

> 部署后你会拿到一个类似 `https://card-party-xxxx.onrender.com` 的网址，
> 把这个网址（后面可以带上房间号）发给朋友就行。

### 方案 A：Render.com（推荐，免费、支持 WebSocket）

**准备：把代码传到 GitHub**

1. 注册 <https://github.com>（免费）。
2. 点右上角 `+` → **New repository** → 名字填 `card-party` → 选 **Public** → Create。
3. 如果不会用命令行，可以直接在 GitHub 网页上点 **Add file → Upload files**，
   把 `card-party` 文件夹里的**所有文件**（**不要**上传 `node_modules`）拖进去上传，然后 Commit。

**部署：**

4. 打开 <https://render.com> → 用 GitHub 账号登录（免费注册）。
5. 点 **New +** → 选 **Web Service** → 找到刚才的 `card-party` 仓库，点 **Connect**。
6. 按下面填（其余保持默认）：

| 字段 | 填什么 |
|---|---|
| Name | `card-party`（随便起，会变成网址的一部分） |
| Region | `Singapore (Southeast Asia)`（离国内最近，其他也行） |
| Branch | `main`（或 `master`，看你仓库默认分支） |
| Runtime | `Node` |
| Build Command | `npm install` |
| Start Command | `npm start` |
| Health Check Path | `/health` |

7. Instance Type 选 **Free**。
8. 点 **Create Web Service**，等 2~5 分钟。状态变成绿色 **Live** 就成功了。
9. 页面顶部会显示你的网址，例如 `https://card-party-xxxx.onrender.com`。

> **关于免费版的休眠**：15 分钟没人访问，Render 会让服务"睡觉"。
> 朋友第一次打开要等 **30~50 秒**才能进（这就是所谓的"冷启动"），之后就秒开了。
> 这是免费方案的通病，觉得慢可以：① 玩之前自己先打开一次把它唤醒；
> ② 或者换 Railway / Koyeb（同样免费，策略略有不同）；
> ③ 或者付费（约 7 美元/月）就不会休眠。

### 方案 B：Railway.app / Koyeb.com

流程几乎一样：注册 → **New Project → Deploy from GitHub** → 选仓库 →
Build Command 填 `npm install`、Start Command 填 `npm start` → 部署完成拿网址。
这两个平台同样从 `process.env.PORT` 读端口，本项目已经处理好了，不用改代码。

### 方案 C：只在局域网玩（不部署，最快）

如果朋友就在你旁边、连着同一个 WiFi，部署都不用做：

1. 在本机启动 `npm start`。
2. 终端输入 `ipconfig`（Mac/Linux 输入 `ifconfig`），找到 **IPv4 地址**，例如 `192.168.1.23`。
3. 让朋友在手机浏览器打开 `http://192.168.1.23:3000`。
4. 如果打不开，多半是 Windows 防火墙拦了：临时关掉防火墙，或在防火墙里允许 Node.js。

### 方案 D：不想上传 GitHub，想让外网朋友玩

用内网穿透工具（cpolar / natapp / 花生壳 等）把本机 3000 端口映射成一个公网网址。
注册后按它们的一键教程操作即可，免费版一般够临时玩几局。

## 六、把链接发给朋友（3 步）

1. 你在网站上点「**创建房间**」，选好游戏。
2. 进房间后点右上角的「**复制邀请链接**」，会复制到类似这样的内容：

```
来一起打牌！房间号：A3K9
https://card-party-xxxx.onrender.com/A3K9
```

3. 微信发给朋友。朋友**点开链接 → 填昵称 → 点「加入房间」**（房间号已经自动填好了）。

> 小提示：
> - 房间号是 **4 位字母数字**（去掉了容易看错的 I/O/0/1）。
> - 朋友也可以直接手动输房间号。
> - 你是房主，可以点「**设置**」调整规则（比如唬牌的质疑倒计时），点「**开始游戏**」开局。
> - 中途有人掉线？刷新页面就会**自动回到原来的座位**，牌还在。
> - 想踢人 / 解散房间，都在底部的房主工具条里（只有房主能看到）。

## 七、以后怎么新增一款游戏

假设你要加一款叫「斗地主」的游戏，模块名叫 `ddz`。一共 4 步（**不用改任何现有逻辑**）：

### 第 1 步：写服务端规则 —— 新建 `server/games/ddz.js`

复制 `server/games/cheat.js` 改名，按这个接口改（这是**唯一的契约**）：

```js
module.exports = {
  id: 'ddz',
  name: '斗地主',
  minPlayers: 3,
  maxPlayers: 3,

  // 房间里可调的选项（房主点「设置」时自动出现）
  defaults: { someOption: 10 },
  optionFields: [
    { key: 'someOption', label: '某个选项', type: 'number', min: 1, max: 100, step: 1 }
    // type 还支持 'bool'、'select'（select 要再加 options: ['A','B']）
  ],
  rules: ['规则第一条', '规则第二条'],   // 点「规则」按钮时显示
  nextLabel: '再来一局',

  // 创建房间时调用一次，初始化 room.state
  init(room) { room.state = { /* ... */ }; return room.state; },

  // 房主点「开始游戏 / 下一局」时调用
  start(room, ctx) { /* 发牌、确定先手等 */ },

  // 玩家每次操作（出牌/过/选牌…）都走这里
  // 返回 { ok:true } 或 { ok:false, error:'提示文字' }
  handle(room, playerId, action, ctx) { return { ok: true }; },

  // 生成"给某个玩家看的状态"—— 别人的暗牌必须在这里藏掉！
  view(room, playerId) { return { ui: 'ddz', /* ... */ }; }
};
```

几个可用的 helper：

- `room.activePlayers()` → 房间里的玩家数组 `[{id, name}]`
- `room.options` → 房主设置的选项
- `ctx.setTimer(fn, 毫秒)` / `ctx.clearTimer()` → 需要倒计时（比如质疑窗口）时用
- `ctx.broadcast()` → 手动广播一次状态
- `require('../../public/shared/cards.js')` → 造牌、洗牌、排序工具

### 第 2 步：注册 —— 编辑 `server/games/index.js`

```js
module.exports = {
  stud5: require('./stud5'),
  cheat: require('./cheat'),
  baohuang: require('./baohuang'),
  shengji: require('./shengji'),
  ddz: require('./ddz')        // ← 加这一行
};
```

### 第 3 步：写界面 —— 新建 `public/js/games/ddz.js`

复制 `public/js/games/cheat.js` 改名，实现：

```js
window.CPGames = window.CPGames || {};
window.CPGames.ddz = (function () {
  function render(root, snap, api) {
    // snap.room  = 房间信息（玩家列表、房主、选项…）
    // snap.view  = 第 1 步里 view() 返回的东西
    // api.meId   = 我的 id
    // api.send({type:'play', cardIds:[...]})  发操作给服务端
    // api.reRender()  只重画界面（比如切换按钮选中态）
    root.innerHTML = '<div class="panel">...</div>';
    root.querySelectorAll('[data-act]').forEach(function (b) {
      b.addEventListener('click', function () {
        api.send({ type: b.getAttribute('data-act') });
      });
    });
  }
  return { render: render };
})();
```

渲染牌用现成的 `UI.cardHTML(card, { size:'sm'|'xs', hidden:true, selected:true })`，
`UI.esc(文字)` 用来转义昵称等文本。CSS 类可以直接复用 `.panel / .seat / .cards-row / .badge / .acts / .btn`。

### 第 4 步：加载脚本 —— 编辑 `public/index.html`

在其它游戏脚本后面加一行：

```html
<script src="/js/games/ddz.js"></script>
```

然后**重启服务**（`Ctrl + C` 再 `npm start`），首页的「选择游戏」里就会自动多出「斗地主」
（因为 `/api/games` 是从注册表自动生成的）。

## 八、一些设计上的说明

- **所有规则判定都在服务端**，客户端只负责画界面。有人改前端 JS 也骗不了牌。
- **每个玩家收到的状态是单独裁剪过的**，别人的暗牌根本不会下发到他浏览器（见各游戏的 `view()`）。
- **房间数据存内存**，服务重启就清空；超过 6 小时无活动的房间会自动清理。
- **掉线重连**：玩家 id 存在浏览器 localStorage，刷新/断网后自动回到原座位。
- **人数**：房间最多 8 人，各游戏有各自的人数下限/上限（保皇 4–5 人，升级固定 4 人）。
- 想长期稳定用，建议把免费平台的休眠问题解决（付费或用 UptimeRobot 之类定时 ping 一下 `/health`）。
